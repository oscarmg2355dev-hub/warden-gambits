# UI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign the map (horizontal 16-bit pixel-art), node text sizes, combo help and the combat screen layout per the UI v2 spec, on top of Combat v2.

**Architecture:** Pure presentation changes in `:app` (Compose). Shared `ComboKeys` composable + key colors in the theme, a deterministic `PixelMap` Canvas renderer, a fixed-proportion combat layout. ViewModels only gain presentation data; no game rules in composables.

**Tech Stack:** Compose + Material 3, Robolectric UI tests, adb for device screenshots.

**Spec:** `docs/superpowers/specs/2026-10-12-ui-v2-design.md`

## Global Constraints

- No game rules in `:app`; `:engine` untouched. No new libraries; no external images (pixel-art drawn by code).
- Key colors exactly: 1 `#C62828`/white, 2 `#0097A7`/white, 3 `#F9A825`/black, ⚔ `#2E7D32`/white; buttons 72 dp high, 12 dp corners, 28 sp labels.
- Node text 18 sp (line height 26 sp), title 24 sp Cinzel; rival lines 16 sp.
- Strings in Spanish (`strings.xml`), code in English. No git. Gradle with `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`. Zero `w:` lines.
- Verification per task: `./gradlew :app:testDebugUnitTest :app:assembleDebug`.

## Review Focus

1. Combat zones keep identical bounds with 1 vs 4 rivals and 0 vs many effects (overflow → "+N"). (Task 4)
2. Map deterministic (same pixels for same zone) and initial scroll centers the current zone, also for the final node. (Task 2)
3. Key colors identical in combat buttons, combo row and help (single source). (Tasks 1, 3, 4)
4. Floating numbers from `EffectTicked` don't spam/leak (keyed, auto-removed). (Task 4)
5. Small phones (360×640 dp): combat fits without scroll, text not clipped. (Tasks 4, 5)
