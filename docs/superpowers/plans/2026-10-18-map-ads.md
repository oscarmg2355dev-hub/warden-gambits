# Publicidad en el mapa (AdMob) — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un banner adaptativo de AdMob, fijo abajo y solo en el mapa: anuncios de prueba en depuración y reales en la tienda cuando exista `admob.properties`, con el consentimiento RGPD de UMP.

**Architecture:** la librería de anuncios va siempre incluida en `:app` (enfoque B). `BuildConfig.ADS_ENABLED` y `BuildConfig.MAP_BANNER_AD_UNIT_ID` deciden si hay anuncios. Un `AdsController` (interfaz) encapsula UMP y `MobileAds` y expone un `StateFlow<AdsState>`. La UI solo lee ese estado: el mapa recibe el banner por una ranura inferior y Opciones muestra el botón de privacidad. `:engine` no cambia.

**Tech Stack:** Kotlin, Jetpack Compose, Google Mobile Ads SDK (`play-services-ads`), User Messaging Platform (`user-messaging-platform`), Robolectric.

**Spec:** `docs/superpowers/specs/2026-10-18-map-ads-design.md`

## Global Constraints

- **Solo `:app`.** `:engine` sin cambios ni dependencias nuevas.
- **Librerías:** `com.google.android.gms:play-services-ads` y `com.google.android.ump:user-messaging-platform`, la última estable de cada una que resuelva con AGP 9.4.1 / compileSdk 36, en `gradle/libs.versions.toml`.
- **IDs de prueba (debug):**
  - app `ca-app-pub-3940256099942544~3347511713`;
  - banner adaptativo `ca-app-pub-3940256099942544/9214589741`.
- **`admob.properties`** en la raíz, con las claves `appId` y `mapBannerId`. Se añade a `.gitignore`. Nunca se sube a git.
- **Release sin `admob.properties`:**
  - ID de app de prueba en el manifest;
  - `MAP_BANNER_AD_UNIT_ID = ""` y `ADS_ENABLED = false`;
  - no se pide consentimiento, no se inicializa `MobileAds` y no se reserva ni se carga el banner.
- **Pantallas:** anuncios solo en el mapa. Ningún vídeo ni intersticial.
- **Textos:** «Privacidad de los anuncios» / «Ad privacy», en `strings.xml` es y en (`StringResourcesParityTest`); en tengwar, por `trText` como los demás botones.
- **Sin git en los pasos:** commits solo si el usuario lo pide. `strings.xml` es CRLF: se conservan los finales de línea.
- **Entorno:** `export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"`.

## Review Focus

1. **Sin red o con el formulario de consentimiento fallido:** el juego arranca y el mapa funciona sin banner ni ranura. → Task 2, `failedConsentDisablesAds`.
2. **Release sin `admob.properties`:** nunca se inicializa `MobileAds` ni se dibuja la ranura. → Task 2, `disabledControllerNeverRequestsAds`, y Task 3, `noBannerWhenAdsCannotBeRequested`.
3. **El mapa no cambia de altura cuando el anuncio carga o falla**, porque se regeneraría el mundo, que tarda segundos: la ranura tiene altura fija desde la primera composición. → Task 3, `bottomBarKeepsMapHeightStable`.
4. **Entrar y salir del mapa muchas veces:** el `AdView` se destruye al salir y no se acumulan vistas. → Task 3, verificación manual del paso 7.
5. **Tengwar e inglés:** el botón de privacidad se traduce y se transcribe; la paridad es/en sigue en verde. → Task 4, `privacyButtonInEnglishAndTengwar`.

**Interfaces:**
- Consumes: `BuildConfig.ADS_ENABLED` (Task 1).
- Produces:

  - `interface AdsController { val state: StateFlow<AdsState>; fun start(activity: Activity); fun showPrivacyOptions(activity: Activity) }`;
  - `object DisabledAdsController : AdsController`: estado siempre `AdsState()` y `start`/`showPrivacyOptions` sin efecto;

  - `fun adsController(context: Context, enabled: Boolean = BuildConfig.ADS_ENABLED): AdsController`, que devuelve `DisabledAdsController` si `!enabled`;
  - `AppContainer.ads: AdsController`.

- [ ] **Step 1: Write the failing tests** `AdsControllerTest` (Robolectric):
  - `disabledControllerNeverRequestsAds()`: `adsController(context, enabled = false)` es `DisabledAdsController`, y tras `start(activity)` su estado sigue siendo `AdsState(false, false)`.
  - `failedConsentDisablesAds()`: llamar a `UmpAdsController.onConsentError(message)`, un método `internal` que llaman los callbacks de error de UMP, deja `canRequestAds = false` y no lanza excepción.
- [ ] **Step 2: Run** `./gradlew :app:testDebugUnitTest --tests "*AdsControllerTest*"`. Expected: FAIL (no existen las clases).
- [ ] **Step 3: Implement.**
  - **`UmpAdsController.start`:**

    - si `canRequestAds()`, `MobileAds.initialize` una sola vez en `Dispatchers.IO` y actualiza el estado con `canRequestAds` y `privacyOptionsRequired`, este último a partir de `privacyOptionsRequirementStatus == REQUIRED`;

  - **`showPrivacyOptions`:** `UserMessagingPlatform.showPrivacyOptionsForm`, que al cerrarse vuelve a evaluar el estado.
