# Warden3 — juego de combate 2D por combos (Android nativo)

Juego de combate 2D para Android basado en **combos**. **Sin gráficos en movimiento**: no hay motor gráfico ni game loop de render. Lo que importa es el **motor de lógica** (reglas, combos, daño, IA); la UI es Jetpack Compose estático que pinta el estado.

> Filosofía y reglas del juego: `descripcion.md` y `docs/superpowers/specs/`. Si algo de este archivo contradice la filosofía del juego, manda la filosofía; avisa y actualiza este archivo.

Idioma: el usuario habla español. Respuestas, docs y strings de UI en español; código, identificadores y mensajes de commit en inglés.

## Stack

- Kotlin (última estable), Gradle Kotlin DSL + version catalog (`gradle/libs.versions.toml`).
- Android: Jetpack Compose + Material 3, una sola Activity, ViewModel + StateFlow. minSdk 26, compile/targetSdk 36.
- Tests: JUnit 5 + kotlin.test en `:engine`; coroutines-test + Turbine para ViewModels; Compose UI test para pantallas clave.
- Sin motores de juego (LibGDX, Unity, Godot, Korge…), sin OpenGL/SurfaceView, sin DI pesada al inicio (inyección manual por constructor).

## Módulos

```
:engine   Kotlin/JVM puro. Toda la lógica del juego. Cero dependencias Android.
:app      Android. Compose UI + ViewModels que envuelven el motor.
(:sim)    Opcional: simulador headless para balance (JVM, depende de :engine).
```

Dirección de dependencias: `:app → :engine`. Nunca al revés.

## Reglas de arquitectura

1. **El motor es puro y determinista**: estado inmutable, `reduce(state, action) -> (state, events)`, RNG sembrado, el tiempo entra como dato. Nada de `android.*`, reloj del sistema ni `Random()` sin semilla en `:engine`.
2. **La UI no decide nada del juego**: los composables pintan `UiState` y emiten intents. Si hay un `if` sobre reglas del juego en `:app`, va a `:engine`.
3. **Datos sobre código**: personajes, movimientos, combos y números de balance son datos.
4. **Sealed interfaces** para acciones, eventos y fases; `when` exhaustivo, sin `else`.
5. **Dependencias de `:engine`**: la única dependencia externa permitida es `kotlinx-serialization-json`.

## Comandos

Requiere `JAVA_HOME` apuntando al JBR 21 de Android Studio (el Java 25 del sistema no vale). Detalles en la skill `android-build`.

```bash
export JAVA_HOME="/c/Program Files/Android/Android Studio/jbr"
./gradlew :engine:test            # bucle principal de desarrollo (rápido, sin emulador)
./gradlew :app:testDebugUnitTest  # tests de ViewModels
./gradlew :app:assembleDebug      # APK
./gradlew :app:installDebug       # instalar en dispositivo/emulador
./gradlew :app:bundleRelease      # AAB firmado para Play (app/build/outputs/bundle/release/)
./gradlew build                   # todo + lint
```

## Definición de "hecho"

- Tests nuevos para el comportamiento nuevo, en rojo antes y en verde después.
- `./gradlew :engine:test` en verde; si se tocó `:app`, también `:app:testDebugUnitTest` y `:app:assembleDebug`.
- Si cambian números de balance: tabla antes/después de la simulación.
- Sin warnings nuevos del compilador en `:engine`.
